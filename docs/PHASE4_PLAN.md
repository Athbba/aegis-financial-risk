## Evidence and proposed remedies

| Risk / severity | Source evidence and impact | Remedy / acceptance evidence |
| --- | --- | --- |
| Known dependency advisories / scanner Critical, application exposure conditional | Spring MVC 6.2.19 remains flagged by two GHSAs. Official Spring rates CVE-2026-47890 Low (SSE view fragments with attacker-controlled data) and CVE-2026-47884 Medium (XsltView, wildcard implicit view rendering). JSON REST currently implements neither feature. Phase 3 checked runtime dependencies only. | Verify primary advisories, compatible/public patch availability, Boot 4 / Framework 7 migration costs. Prototype supported versions without forcing Framework 7 under Boot 3. Adopt if original numerical/security/API/browser contracts pass; otherwise retain explicit findings and test guards against vulnerable application features. Expand inventory to test dependencies and scan actual runtime images where tooling/network allows. No suppression masquerading as resolution. |
| Unbounded password work and account guessing / High | AuthController/AuthService call BCrypt without rate limits; no temporary throttle; duplicate-email registration conflicts reveal availability. | Persistent PostgreSQL attempt buckets for client address and normalized account hash, bounded windows with Retry-After; no permanent account lockout or forwarded-header trust. Validate lock expiry, concurrency, successful login reset, unknown accounts, IP spoofing, generic failures and restart persistence. Document NAT/distributed-abuse limitations. |
| Payload/resource exhaustion / Medium | No JSON body cap; nested/oversized input reaches JSON parsing. Pagination and risk/trade domain limits already exist. | Enforce small byte limit on known/streamed JSON bodies, parser depth/string/number constraints, and proxy body cap. Test content-length and unknown-length oversized requests and malformed input. Preserve risk scenario limits. |
| Refresh/response-loss duplicate intent / High | TradingService correctly locks, compares semantic payloads and commits atomically; TradeTicket remembers an intent only in a React ref and changes key after edits. | Persist only unresolved intent/key in tab sessionStorage before submission; freeze ambiguous intent; owner-scoped exact key lookup; recover after refresh/login and retry the same key. Never infer failure from 5xx/timeout or a temporarily absent lookup. Test commit-then-disconnect, refresh, service recreation/retry, concurrent duplicates and rollback. Keep transactions, immutable history and FIFO unchanged. |
| Diagnostic gaps and unsafe exception logging / Medium | Structured logs exist, but no request correlation; errors log raw exception text; trading log is a processed request rather than a commit receipt. Only generic health is exposed. | Server-generated request IDs, bounded route/outcome tags, safe error logging without payloads/headers/secrets, transaction completion counters/logs, liveness/readiness and separately authenticated read-only operations metrics. Test ID propagation, redaction, metric counters and denied user access to operations endpoints. |
| Runtime database owner privileges / High | Compose POSTGRES_USER=aegis owns objects and can bypass append-only triggers. No tested least-privilege alternative or restore runbook. | Explicit migration-only command, optional runtime grants without DDL/history mutation, credentials separated between migration and serving processes. Verify grants and V2→new migration on disposable PostgreSQL, preserve existing financial row content, and restore a custom dump into a newly named disposable database. Never drop/restore the active volume. |
| No independent read-model reconciliation / Medium | Accounting invariants checked during execution and historical valuation, but no operational comparison of mutable book to immutable records. | Owner-scoped read-only reconciliation of cash, lots, orders, allocations, ledger and audit references. Tests detect deliberate disposable-fixture corruption without modifying/repairing history. |
| Performance assumptions without measurements / Medium | Date/asset/order bounds and bulk reads exist; no reproducible measured baseline. | Dedicated benchmark on disposable PostgreSQL with fixed input sizes and warmup; report JVM/CPU/memory, operation counts and min/p50/p95/max for create/trade, valuation, risk, stress and paginated history. Optimize only observed material bottlenecks; no invented numbers or production throughput claims. |
| Local security boundary / Medium | Session cookie HttpOnly/SameSite Strict, CSRF, ownership and API CSP already enabled; Secure is optional for local HTTP. No CORS allowlist is needed for same-origin. | Preserve tests; explicit same-origin/header/method controls and secure-cookie configuration checks. Operational endpoints must not inherit normal user access. Document HTTPS requirement, restart session loss, credential rotation and remaining abuse/recovery limits. |

## Delivery sequence

1. Commit this audit/acceptance plan. Evaluate and verify the dependency migration before other backend changes.
2. Implement request/security/observability controls with negative PostgreSQL tests; retain all earlier tests.
3. Add recoverable order intent and reconciliation; browser journeys exercise real post-commit response loss, refresh and retry.
4. Add least-privilege/migration/backup tooling and disposable database recovery/grant tests; benchmark isolated synthetic portfolios.
5. Run complete feasible regressions, formatting/build, dependency/image/secret checks. Record failures and limits honestly in PHASE4_SECURITY_REVIEW.md and TESTING.md. Commit/push feature branch and open PR to main; never merge automatically.

## Engineering constraints

No new distributed services, monitoring stack or paid credentials. Use Actuator/Micrometer and PostgreSQL already present. Authentication controls must not log raw email/password/IP/cookies/session identifiers or trust arbitrary X-Forwarded-For. Metrics labels exclude portfolio IDs, users, request IDs, raw paths and business inputs. Logs distinguish expected business rejection from infrastructure rollback. Operational scripts require explicit disposable restore targets and keep dumps/credentials outside Git. No claim of production readiness from passing tests.
