# Phase 5 image and deployment security evidence

See [release table](PHASE5_RELEASE.md) for current results, immutable identities and remaining blockers. No exception has been granted for a Critical/High finding. No broad ignore, ignore-unfixed, severity reclassification or TLS bypass is used.

## Image decisions

- API uses supported `eclipse-temurin:21-jre-alpine` at immutable publisher digest `sha256:51ab5e3302e7141ce665ca3ea85e8b5cd648eafbc3c0c90dd79d6537684e4555`. This publisher image does not contain Ubuntu's pebble Go executable, so the three High findings in that unused tool are absent. The application has no server-side font/image rendering (all charts are React/SVG); its optional fontconfig/ttf-dejavu APK packages are removed using the publisher's installed package database. Native server font rendering is outside this application image's supported feature set. It retains the JRE/cacerts; Java 21, decimal serialization, financial fixtures and full-stack risk/trading tests remain required. This is a supported image change, not deletion of a certificate tool or unverified replacement binary.
- PostgreSQL remains the official 17 Alpine publisher digest `sha256:b0f9560a2de083e2cc7382e75f808c7381a32852a7ec49117deedb300e552b24`. The only removed executable is `/usr/local/bin/gosu`. Source inspection shows the official entrypoint calls it solely in its uid=0 branch. `deploy/database.Dockerfile` always runs uid 70, including initialization; new-volume initialization, migration, serving, backup/restore, restart and trading are tested without it. No alternative gosu binary is downloaded. Root-starting this derived image is unsupported; deployment validation requires user postgres and the real rehearsal checks effective uid. The Critical CVE-2025-68121/24 High bundled Go-library findings cannot reside in the removed executable. Removing the executable is justified only for this explicitly non-root startup path.
- UI keeps official `nginxinc/nginx-unprivileged:stable-alpine` digest `sha256:782bb89768cc87b7f95c18b95baa1af250e5d451f26794f59363540161147c01`. Its optional nginx-module-image-filter package is removed through APK because neither Nginx configuration loads/uses image_filter; static files, TLS and reverse proxying do not require it. All final application layers, not just these bases, are scanned.

A refreshed final scan initially found new **High CVE-2026-77214** and Medium CVE-2026-102633 in libexpat 2.8.5-r0 (fix 2.9.0-r0) in both API/UI. The gate blocked correctly. Publisher tags were repulled and remained unchanged; the official Alpine repository still returned proxy CONNECT 403. Inspection traced libexpat to optional fontconfig: API via ttf-dejavu, UI via libgd/nginx-module-image-filter. Removing those **unused packages with `apk --no-network del`**, rather than deleting a shared library or suppressing the scanner, also removes their unneeded libexpat/libpng dependencies. This does not install a replacement or fetch unverified content. Keep this reduction only with Java/cacerts checks, real non-root startup and complete trading/risk/HTTPS/accessibility regression evidence. Future server-side font/image features require a new supported, scanned dependency design.

Remaining **Medium** finding: zlib CVE-2026-85091 (`1.3.2-r0`, fix `1.3.2-r1`) in API/UI/database. The former Ubuntu distribution package is absent after the supported API base change, but that does not resolve Alpine's zlib finding. Fix availability is reported by the scanner; a current official-repository attempt was denied with proxy CONNECT **403**. No unverified mirror, stale-index override or TLS bypass was used. Compression libraries remain potentially relevant to serving software; do not call the Medium finding resolved or harmless. Rebuild from verified publisher/package fixes and rescan. Any new Critical/High blocks the gate regardless of reachability assessment.

## Evidence and fail-closed policy

`install-release-scanners.sh` obtains pinned Trivy 0.76.0/Gitleaks 8.30.1 assets from official GitHub releases over validated TLS, verifies publisher SHA-256 manifests and supports linux/amd64. Runtime base references are registry digest-verified. Another architecture needs native verified tools and a separately tested platform; this rehearsal does not claim arm64 execution.

`scan-release-images.sh` explicitly refreshes the official vulnerability DB; failure stops immediately. Each final image is scanned without severity filtering, produces full sanitized JSON and CycloneDX SBOM, and is exported to a local OCI-layout archive. No registry push occurs. Runtime credentials are file mounts, never build inputs. Sanitization removes image environment/history fields; no private container inspection, scanner logs, browser traces, dump/key files or session artifacts are uploaded. Safe OCI artifacts contain only the reviewed images, not runtime mounts.

The manifest records source commit, per-image revision/ID/platform, immutable OCI archive SHA-256, report/SBOM SHA-256, scanner version and vulnerability/Java DB timestamps. `verify-release-evidence.py` requires all three reports/SBOMs/archives, matching image/source identities/checksums, supported platform and both DB timestamps no older than **48 hours** (future timestamps also fail). Download time does not reset DB age. Zero Critical/High is required; Medium/Low/Unknown remain fully visible. Missing evidence, scanner/network errors or stale databases are release blockers. Fixtures prove vulnerable output, missing/stale output, artifact damage and scanner/network failure cannot pass.
