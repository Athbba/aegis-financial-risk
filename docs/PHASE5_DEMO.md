# Reproducible synthetic presentation

Use only the isolated local HTTPS rehearsal in [the runbook](PHASE5_DEPLOYMENT.md). No host/domain is selected and no public launch is authorized. The interface and financial formulas retain the AEGIS identity; no performance prediction, investment advice or institution-grade risk claim is made.

1. Open the loopback HTTPS entry with the disposable CA explicitly trusted, or the eventual authorized target with its valid certificate. Never bypass the certificate warning. Enrollment is closed by default; use only an explicit supervised local test window. Use a new throwaway account; no private financial data is needed.
2. Create **Synthetic teaching portfolio**, initial cash **10,000 USD**. Buy **10 ALTA** with execution date **2024-01-02**. Optionally buy **5 BRIM** on the same date. Those are fictional assets using persisted deterministic prices, not manually injected chart values.
3. Select **Risk Lab**, as-of **2025-12-31**, **730 calendar days**. Read the live backend volatility, VaR95/99, exposures, distribution and actual historical-equity drawdown. Cash contributes zero price exposure. Insufficient samples and missing dates must remain named unavailable states.
4. Focus the VaR terminology button with the keyboard to read its explanation. Focus the common-shock slider and use arrow keys. Compare an illustrative common −10% scenario with a custom BRIM override. Confirm the assumptions, unchanged cash, asset contributions and original order history. VaR is not a maximum-loss promise; stress is hypothetical repricing, never execution.
5. Move to history/positions on a narrow viewport. Tab into the newly focusable, named scroll regions and use arrow keys to inspect columns. Skip-to-content, form labels, focus outlines and chart/table alternatives remain available. Desktop/mobile Axe checks include WCAG A/AA/2.1 AA rules and contrast; this is not a full screen-reader/physical-device audit.
6. Demonstrate reliability with `recovery.spec.ts`: commit a trade but lose its response, retain the intent/key, refresh, restart the private API, sign in again and recover exactly one order. Do not clear sessionStorage or choose another key while confirmation is uncertain.
